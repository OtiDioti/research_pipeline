## Settled boundary

1. Add strict versioned typed Source content for the existing source envelope kind. Preserve a stable declared work identity, separately represented upstream identity/version (explicit unknown permitted), local capture identity/revision supplied by the envelope, bibliographic title/authorship with unknowns represented honestly, supplied/retrieval provenance, access/reuse/confidentiality/external-processing declarations, original artifact inventory, extraction lineage, exact locations, reported reading coverage, source-attributed statements and limitations. A paper version, captured bytes/metadata revision and a reading-report revision are distinct. The Architect must prescribe concrete bounded value/signature/serialization contracts before the Writer implements them; avoid a generic unvalidated metadata bag for these required concepts.
2. Support multiple original files and derived extraction artifacts without executing a parser/OCR/tool. Derived artifacts record their exact original inputs, declared parser/tool identity/settings, output references, location mappings and warnings. Every artifact link must project into the envelope consistently and be verified by existing admission. Exact locations remain explicit named page/section/equation/theorem or byte/line descriptions, never inferred scientific equivalence. Declared coverage distinguishes uninspected, metadata/abstract-only, selected material, whole-document examination and any reported reproduction; byte capture or extraction success must never automatically upgrade coverage or certify reproduction. Keep statements attributed, and distinguish source statements, interpretations and separately referenced checks. A stored declaration does not authenticate the actor or establish actual execution/endorsement.
3. Keep version-1 scientific, assessment and work-product codecs unchanged. Add explicit Source dispatch through the existing typed boundary. Define an exhaustive reference traversal table, preserve all existing shallow source-link semantics and legacy generic payloads, and do not turn references into approval or exposure certificates. Exact same-source predecessor references, if used, obey immediate-predecessor revision semantics; related upstream works remain distinct and explicit. New source versions/corrections retain old bytes, metadata, uses and receipts without silently moving an old reference. State stays null; no claim promotion, project readiness or tool enablement.
4. Add an explicit bounded local-file capture/preparation operation. It accepts a trusted selected input root, an ordered explicit nonempty file selection with portable logical names, complete source metadata, caller-specified identity/revision/expected-head/submission ID and explicit provenance, plus required finite per-file/aggregate/count bounds and trusted exclusion roots. It captures only supplied local files into existing immutable artifact storage, produces a detached saved canonical Submission and meaningful exact byte/provenance mapping, and leaves commit visibly separate through submit_typed. Reuse the existing bounded no-follow file/ancestor handling where appropriate; any focused extraction must preserve accepted public behavior/tests. No directory crawl, globbing, archive expansion, network fetch, dependency installation, configuration activation, parsing or content execution.
5. Bound before allocation and detect source growth/truncation/in-place changes, same-byte inode replacement and ancestor rebinding during capture. Reject selected symlinks, FIFOs/devices/sockets/directory leaves and unsafe file/ancestor ownership or writable-link arrangements under an explicit documented local contract. Treat scripts/notebooks/configuration as inert bytes. Preserve original bytes, modes and organization; no chmod/repair/cleanup of supplied inputs. Require trusted explicit software-source/runtime/backup/control exclusions rather than deriving permissions or paths from metadata. Original path/provenance strings are data, never later executable instructions or authority. Publish only through the existing artifact store; failed preparation may retain unreferenced objects but writes no application metadata or submission reservation.
6. Validate the complete prepared request using the existing read-only typed admission path, then commit only the saved exact Submission. Preparation does not prove future admission; existing CAS protects competing captures and existing original-ID-first reconciliation protects lost acknowledgment. Saved proposal serialization must be strict, deterministic and pure, preserve IDs/timestamps/order and reject missing nested fields, duplicates, unknown versions/coercion and forged nested values. Do not reuse the work-product-only proposal format for source records or change its behavior. An identical saved retry after input changes/deletion, head advances or artifact loss returns its original receipt; changed reuse conflicts. New edits/captures use a new submission ID.
7. Local capture records actual supplied provenance and exact resulting hashes, never invents a download receipt, read coverage, expert audit, license permission or upstream version. Metadata declarations may describe limited/unavailable information without pretending full text was inspected. Represent unknown restrictions explicitly; no operation in this request discloses data externally or enforces a fictional broader authorization system. Permission enforcement for future live acquisition/processing and scientific readiness remains separate required work. New fixtures are deterministic synthetic development materials only; no real external/private data ingestion.
