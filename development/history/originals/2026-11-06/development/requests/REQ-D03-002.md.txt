## Goal and dependency evidence

Persist an explicitly selected collection of existing scientific material as a strict, versioned corpus inventory. Keep its original baseline, exact Source versions, original-path mappings, unresolved items, attributed inspection declarations and link relationships recoverable through correction, restart and backup. This advances R-004/R-008/R-019/R-021/R-022/R-024 and the recording subset of R-029, under specification §§3.2, 5.1, 9.1–9.3, 9.5, 9.10 and 10.1. It supplies an engineering prerequisite for project intake and readable views; inventory is not readiness, understanding, permission or scientific support.

Read those original specification sections, docs/sources.md, docs/source-capture.md, docs/durable-records.md, docs/work-products.md and existing domain/source/store/backup tests. The eight typed content kinds, Source capture/proposals, CAS/idempotency and verified schema-2 backups are accepted dependencies. Do not depend on ignored coordinator files or on an editable installation of the original checkout.

Only the delegated CWI Writer implements product changes in this assigned worktree. No recursive CWI, direct original-checkout edits, intentional staging/committing/ref operations, backend maintenance or changes to administrative authority, frozen acceptance, specification or historical fixtures.

## Settled design and interfaces

Use the existing `corpus_manifest` envelope kind, schema 2, immutable revision store and `RecordStore.submit_typed` / `get_typed_revision`. Add a pure `research_pipeline.corpus` module with an explicit new version-1 content discriminator, frozen bounded value types, strict deterministic JSON and exact envelope conversion. The public entry points follow the existing module convention: `decode_content`, `dumps_content`, `loads_content`, `encode_envelope`, `decode_envelope`. The Architect prescribes all concrete constructor/signature/wire fields, enums, bounds, error classes, allowed paths and reference traversal before the Writer implements them. Required concepts below must use validated fields, not an arbitrary metadata bag.

1. A manifest has a stable corpus identity supplied by the envelope, an attributed title/purpose/selection provenance, ordered inventory entries, explicit collection-level limitations and a revision relationship. Revision 1 is the original baseline. Every subsequent typed revision must explicitly reference the same identity's immediately preceding typed manifest; preserve the complete chain to revision 1. Do not reinterpret a generic historical corpus as a certified typed baseline. Corrections and additions are new full inventory snapshots with an attributed reason; old entries, mappings and bytes remain available through history, not silently rewritten. Entries have stable opaque IDs independent of path/title/hash; do not silently retarget an entry's original identity when correcting a capture. Define and test how entry corrections, additions and removals are represented and distinguished. No inference of scientific equivalence from matching titles, paths or byte hashes.
2. Entries distinguish captured material from references-only, unavailable and unresolved inventory observations. A captured entry pins an exact typed Source revision and identifies the original Source artifacts it includes by artifact ID, preserving origin collection/locator and original-path-to-captured-artifact mapping. Verify actual membership and exact captured identity under typed admission; derived extraction outputs cannot masquerade as originals. Multiple original files, repeated bytes, similar names, different upstream versions and related license/data/instruction material remain distinguishable. A missing or inaccessible item carries an explicit reason, actual known/unknown provenance and no fabricated byte reference. Allow a partial or even empty setup inventory, clearly documented as insufficient by itself for main research; this request implements no research admission endpoint.
3. Classification distinguishes research notes, published sources, derivations, notebooks/calculations, software, data, prior reports and operating instructions, with an explicit other/unknown route. Preserve known/unknown authorship and original provenance through the exact Source or explicit unresolved-item declaration. Source restrictions are retained through pinned Source revisions; unresolved entries retain explicit unknown/reported restrictions. Corpus fields cannot broaden Source access/reuse/confidentiality/external-processing declarations or grant operating policy. Stored paths, URLs and imported instructions are inert provenance strings, never opened, crawled, executed or normalized into filesystem authority.
4. Preserve attributed intake observations: inspected subset and uninspected remainder, exact original Source location references where inspection is declared, relevance/purpose notes, unresolved contradictions/gaps and proposed questions/baselines where supplied. Keep attributed observations distinct from the Source's own reading report and from scientific assessment. No content sniffing, automated substantive-material verdict, inferred coverage, invented expert judgment or fabricated calculation. Validate exact location membership whenever an observation pins one; missing/broken mappings are explicit unresolved observations, not successful resolutions.
5. Preserve original links and accompanying relationships as explicit inventory declarations. For each represented link, retain its source entry and original locator/text, and distinguish a resolved inventory-entry/Source-location target from unresolved or external targets. Validate local entry and exact location targets, including those involving the same Source more than once. Do not fetch external links or traverse arbitrary metadata. Duplicate/version/related-item relationships must have explicit attribution; matching hashes alone do not assert equivalence. Candidate-bearing seed exposure may be recorded as a declaration with unknowns, but does not authenticate a session exposure log or certify independent checking. Document that whole-vault link extraction, visibility enforcement and readiness remain later work.
6. Publish an exhaustive semantic traversal/projection table. New constrained Source and corpus predecessor edges validate supported typed payloads and exact metadata relationships in the existing transaction; all old shallow edges remain shallow even if they now name a typed corpus. Reuse existing closure caching, checking each incoming role independently. Preserve the existing rule that transitive typed closure does not reread artifact bytes. If the manifest directly projects selected original artifacts, exact references must match the Source selection and existing direct-artifact verification applies; the Architect must settle and document this projection explicitly. Do not accidentally certify availability of an entire transitive source graph.
7. Canonical operational/scientific states stay null. No project-ready status, authority grant, approval, tool enablement, task admission, exposure certificate, scientific promotion or current support transition arises from saving or reading a manifest. A later project setup/readiness request will consume this inventory and implement the missing procedural/authority boundaries. Existing codecs, generic submission semantics, Source capture/proposals, work-product round trips, old schema compatibility and historical receipts remain unchanged.
