# Record templates

Indexes reusable development record formats and distinguishes issuance proposals from actual authority and execution evidence.

Use these as short structured records, not as a requirement to duplicate the entire project description.

- [PHASE](PHASE.md): outcome, dependencies, scope and completion.
- [REQUEST](REQUEST.md): executable implementation slice.
- [RUN](RUN.md): evidence-linked result and integration record.
- [DECISION](DECISION.md): consequential choice and alternatives.
- [LIVE_HANDOFF](LIVE_HANDOFF.md): ignored local observation during a run.

Every substantial field must contain evidence, an explicit unknown, or a precise next action. Avoid automatically copying stale values from the preceding run.

Additional templates: [BACKEND_CHANGE](BACKEND_CHANGE.md) for necessary backend modifications and [COMPLETION](COMPLETION.md) for an evidence-linked scoped verdict. [COMMISSIONING](COMMISSIONING.md) and [ACTIVATION](ACTIVATION.md) are first-time issuance forms, not grants. [AUTHORIZATION.md](../AUTHORIZATION.md) is the effective-authority view linked to actual human source records; do not fill it as a blank template. Existing commissioned/activated work uses [continuation](../CODEX_START.md).
