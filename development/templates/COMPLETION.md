# Development completion report — named scope

**Verdict:** COMPLETE / IMPLEMENTATION_SCOPE_COMPLETE_WITH_EVALUATION_PENDING / INCOMPLETE / BLOCKED.

## Scope and authority

Actual authorization ID/revision, specification commit/hash, phases and exact requirement IDs covered, explicitly excluded scope and authority. Do not call a narrower release the completed full project.

## Integrated source

Exact accepted product revisions and CWI receipt references, final integration source revision, subsequent administrative checkpoint, clean-checkout verification, reconciled run/attempt list. No invented self-referential final commit hash: record the assessed parent/source identity and link the eventual report commit afterward where necessary.

## Evidence

Requirement-to-test/review crosswalk; whole-product tests with meaningful execution counts; clean-environment installation and smoke test; representative workflows; interrupted-run/backup/restore evidence; source/vault navigation; isolation/security checks; real-provider and scientific-pilot evidence as required.

## Remaining limits

Unverified providers/platforms/tools, known defects, required human judgments, blocked mandatory obligations, authorized deferrals, scope of statistical/scientific conclusions. Distinguish mocks from live execution and compilation from proof.

## Operational handover

Actual run commands; dependency/model/environment contract; expected permissions and resource limits; recovery/backup instructions; backend repair log and patch recovery; recommended next scientific or development action.

## Final gate

State which completion conditions were satisfied, which were not, and why the verdict follows. A full-project verdict requires all mandatory scope obligations and required human acceptance; code presence, a green unit suite, or successful CWI exit alone is not enough.
