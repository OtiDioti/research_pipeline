## Required contract

1. Use the existing SQLite store and ArtifactStore. Provide a small explicit trusted-controller backup/inspection/restore API, documented with source-local examples. No source-root default, import-time effects, network access, added dependency, generic SQL/worker write endpoint, destructive cleanup, or automatic repair. Product runtime and backup paths are explicit and outside software source.
2. Capture a consistent metadata snapshot using SQLite's supported snapshot/backup mechanism rather than copying a live database file. Artifacts come from the exact captured metadata, including historical revisions, not only current heads. Later source writes must not create a mixed-generation backup. There is no artifact garbage collector; retain source state unchanged.
3. Version the backup format and bind its schema, snapshot metadata digest/size and complete referenced-artifact digest/size inventory in a strict manifest. Backup identity/integrity is distinct from scientific correctness and from a signature by a trusted external authority. Do not include credentials, unrelated files, uncommitted staging files or unreferenced orphan bytes. Preserve original committed submission/record/event provenance without generating replacement scientific identities.
4. Verify every copied artifact against the metadata and actual bytes. Ensure metadata/manifest/inventory consistency, useful failures for missing or corrupt referenced objects, and durable complete publication. A failure must not return success or leave a partial backup that inspection regards as complete. Preserve an existing destination and all source bytes. The Architect chooses simple exclusive staging/publication mechanics; document any incomplete directory left after failure, without sweeping it away or pretending it is valid.
5. Backup inspection validates version/schema compatibility, metadata structure and integrity, strict manifest parsing, and every referenced artifact. Reject malformed/duplicate/extra or missing entries, inconsistent sizes/hashes, path-like identifiers, absolute/parent traversal, unsafe symlink/nonregular files, tampering and unsupported versions. Avoid following unsafe backup paths. There is no automatic migration, regeneration or permissive fallback.
6. Restore only into an explicitly selected absent runtime destination. Never merge into or overwrite an existing project or silently change a backup. Verify the complete backup and use durable artifact-before-metadata publication, with a clear final visibility boundary. Expose a usable RecordStore only when complete; detect interrupted restore rather than treating missing work as a successful restoration. Files retain the private ownership/read-only object protections of the accepted store.
7. Restored public reads and histories, current heads, exact links, receipts, canonical duplicate detection and event sequence must match the snapshot. The restored store must accept new appends and independent new artifacts while the source and backup remain unchanged. Exact retry of a pre-snapshot committed submission returns its original receipt, even after a later append; conflicting reuse still fails without effects.
8. Support the actual current version-1 database and reject unsupported backup/schema versions without rewriting originals. A read/export-compatible path for future migrations is valuable, but do not invent a meaningless schema migration or claim general migration support. Document reliable local POSIX/SQLite/filesystem assumptions, bounded lock behavior, and the same trusted-owner boundary as the existing store. Full power-loss guarantees beyond tested barriers, hostile owner protection, distributed filesystems, and periodic scheduling are not claimed.
