## Required behavior

1. `research_pipeline` imports from the current candidate's `implementation/src`, not another installed checkout. Importing it creates no files, starts no models, and performs no network request.
2. `python -m research_pipeline --help` explains this is a foundation with no research execution yet. `--version` prints the same version as package metadata. An unknown command/option returns a nonzero usage error. These commands are tested in subprocesses with explicit candidate-source paths.
3. `python3 -B implementation/scripts/validate.py` works when called from the repository root and resolves its own candidate paths. It returns zero only when layout and the configured meaningful test suite pass, including at least one genuinely executed, non-skipped successful case.
4. The validator rejects unexpected non-Markdown regular files and root symlinks. Directories are allowed. Git's normal `.git` directory and its legitimate linked-worktree pointer file are allowed. Required top-level documentation is checked without rewriting it.
5. The validator does not silently pass missing/empty/all-skipped/failing/erroring test suites. It does not recursively invoke itself when running its own tests. It reports counts and useful failure information, not an unconditional success sentence.
6. Validation uses deterministic local fixtures, disables bytecode/cache writes where relevant, and leaves tracked source unchanged. It must not install dependencies during a frozen validation run.
7. The implementation satisfies the externally supplied frozen bootstrap candidate check as well as its own validator. The exact accepted candidate must differ from the documentation-only baseline.

## Acceptance criteria

- AC-D01-01: All required foundation files exist with coherent responsibilities, valid Python/metadata, and no prohibited root artifact.
- AC-D01-02: CLI tests demonstrate help, consistent version, invalid invocation handling, no import side effects, and candidate-local source loading.
- AC-D01-03: Validator tests demonstrate success for an actual small passing fixture and failure for missing/zero/all-skipped/failing suites and forbidden root files. A legitimate Git worktree marker is accepted. Tests use temporary directories and are not tests that merely assert literal constants.
- AC-D01-04: The frozen bootstrap check executes non-skipped tests from the actual candidate, then invokes the permanent validator; both pass without source mutations.
- AC-D01-05: Documentation states exact commands and current limits. No provider/tool is mandatory, no scientific capability is falsely advertised, and no deferred major component is disguised as implemented by a placeholder.
- AC-D01-06: Final CWI review assesses the meaning of the tests and bootstrap obligations. A positive exit code, file count, or no-op candidate alone is insufficient.
