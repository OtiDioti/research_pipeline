## Settled engineering contract

1. Add immutable/detached typed Python values and strict round-trip codecs for the four scientific content kinds. Concrete small signatures/module names belong to the Architect. Use an explicit content-format discriminator and version 1 inside the existing RecordEnvelope.content; the SQLite schema and backup format remain version 1. Do not reinterpret arbitrary old JSON as typed scientific content, migrate originals or add kinds to SQL. Unknown format/version, missing/extra keys, coercions, invalid JSON/Unicode, malformed references and invalid field types fail with useful errors. Reuse existing canonical JSON and reference validation where appropriate.
2. **Research context** explicitly carries question, equations, definitions, units, conventions, mathematical domains, boundary/initial conditions, parameter regime, approximations and limit ordering. Use required named fields, text for scientific statements and ordered lists where multiple statements are natural. Explicit empty collections may mean none declared; no silent defaults that erase scope. Required question and supplied statement strings are nonblank. Do not parse/evaluate mathematical text or invent a formal language or claim to detect scientific completeness. Preserve all supplied scope exactly without trimming away meaningful notation.
3. **Claim** carries precise statement, descriptive category, explicit quantifiers, one exact context revision, assumptions, approximation qualifications and open obligations. Category is a nonblank descriptive string, not a purported exhaustive scientific classification. Assumptions are local named statements (unique opaque label plus nonblank statement), bound by their containing exact record revision; they are not proofs or mutable global names. Quantifiers/qualifications/obligations are explicit ordered text collections. All claims remain provisional under the existing envelope rules.
4. **Justification** carries one exact context, an explicit ordered conjunction of premise claim revisions, local named required assumptions, method, one or more conclusion claim revisions, zero or more evidence revisions, and explicit limitations. Empty premise collections are permitted for provisional routes without recorded premises and must not imply an axiom/proof. Every listed premise is jointly required; alternatives are separate justification records, never an OR flag on premises. Method/limitations are attributed descriptions only. Provisional conceptual cycles/self-references are allowed and round-trip; accepted deductive support and cycle rejection at endorsement remain future work. Do not automatically assess sufficiency, validity or implication.
5. **Evidence** carries exact artifact references (at least one), one exact context, a nonblank target-property description plus zero or more exact target claim revisions, method, exact input record revisions and/or artifact references, tested scope, result, uncertainty details and failure details. Empty input/uncertainty/failure collections are explicit, not evidence of absence of uncertainty. Origin is restricted in this slice to `synthetic` or `unverified`; there is no authentic-execution constructor or switch. Mark these as declared provenance, not trust/authenticity. Later authentic tool-execution records require their own controller receipt contract. Text claiming execution/approval cannot acquire privileges or supported disposition.
6. Encode semantic record/artifact relationships into the existing envelope's persisted record_references/artifact_references with unambiguous deterministic relationship labels and ordering. Typed content and stored links must agree exactly; reject missing/extra/substituted links on typed decode and submit rather than allowing two conflicting graphs. All semantic references identify identity, revision and expected kind where constrained. No implicit latest lookup. Duplicate references within a semantic collection are rejected where redundant; a target may legitimately appear in different roles (e.g. a provisional self-premise/conclusion), without losing role identity. Preserve conjunction/route boundaries.
7. Provide a narrow typed submit/read boundary over RecordStore with explicit creation provenance, submission identity and expected heads, supporting heterogeneous typed batches and exact same-batch forward references. Every constrained target must resolve to the right kind and supported typed content, either in that batch or immutable committed history. An untyped legacy context/claim/evidence is not silently accepted as a typed target. Arbitrary evidence inputs may reference existing generic kinds with exact identities, but do not become typed scientific endorsements. New typed submissions must reject malformed target content or semantic-link inconsistencies without any metadata/head/event/submission effects. Trusted raw RecordStore remains a low-level generic API, explicitly documented as not a scientific admission gate; no worker endpoint is added.
8. Preserve atomicity, expected-head CAS, revision preservation and exact duplicate/conflicting-ID behavior. Typed exact retry of an already committed identical request returns its original receipt even after heads advance or attached artifact bytes later become unavailable; do not let eager artifact/target reads accidentally defeat the accepted idempotency contract. A conflicting reuse must still fail with no effects. Use a coherent implementation with the existing transaction boundary; do not add unrestricted callbacks, mutable bypass flags, a second database, replacement receipts or SQL migration. Exact immutable-reference validation may rely on append-only storage only if the reasoning and concurrency boundary are documented and tested. A new claim revision may deliberately reference an older context; it must never be silently rebound to its current head.
9. Typed reads reconstruct detached values from the exact stored revision and check content/link coherence. Generic reads/backups keep original bytes and identities. Restoration of typed records uses existing backup mechanics and original receipts; future scientific evaluation must not retroactively promote them. Imports remain inert, stdlib only, explicit runtime paths outside source, no dependency/config/validator changes, no live tools or providers.
