# Backend incident records

Defines the home of detailed backend-maintenance evidence while the root audit remains a concise index.

Use one CP-ID.md record per diagnosed incident or separately authorized backend task, following [BACKEND_CHANGE](../templates/BACKEND_CHANGE.md). Keep every attempted,rejected,reverted and adopted variant with its own time,source/check evidence and disposition; later success never deletes earlier failures or replenishes allowances.

While a product run is live or base-bound, keep pending detail under ignored local/backend-maintenance/. At the first safe checkpoint,track the incident record here and add or update its link/disposition in [the root index](../../coding_pipeline_changes.md). Store reviewable patches under [backend_patches](../backend_patches/FOLDER_CONTENT.md) or retain protected backups. Routine product runs that leave the backend unchanged use their own run records.

CP-001–CP-003 are extracted from the preserved historical audit without changing their adopted revisions,tests,limits or authority. No new backend repair or attempt occurs in this documentation cleanup.
