# Pure lifecycle report rendering

`research_pipeline.lifecycle_report_rendering` renders a detached, first-capture
[LifecycleSourceObservation](committed-lifecycle-sources.md) as generated bytes.
It preserves original intent separately from the later captured control state.
Structural consistency proves neither persisted origin nor artifact availability,
current permission, scientific validity, process termination or readiness.

## Public API

```python
from research_pipeline.lifecycle_report_source import LifecycleSourceObservation, LifecycleSourceLimits
from research_pipeline.lifecycle_report_rendering import (
    LifecycleRenderLimits, LifecycleRenderArgumentError,
    LifecycleRenderValidationError, LifecycleRenderLimitError,
    render_lifecycle_report,
)
```

```text
@dataclass(frozen=True, kw_only=True)
class LifecycleRenderLimits:
    source: LifecycleSourceLimits
    max_work_bytes: int
    max_output_file_bytes: int
    max_output_total_bytes: int

render_lifecycle_report(observation: LifecycleSourceObservation, *,
                        limits: LifecycleRenderLimits) -> dict[str, bytes]
```

All four fields are required. The three scalar allowances are ordinary integers,
excluding booleans, floats and integer subclasses. Work is in `1..2**63-1`;
each output allowance is in `1..64*1024*1024`, inclusive. Every call validates and
detaches the exact limits class and all nested source limits, including instances
mutated around frozen-dataclass protection, before reading observation content.
There are no defaults, result wrapper, supplied receipt, callback, store method,
wire-form renderer overload or output codec. Existing bounded source constructors
and `loads_observation(data, *, limits)` are the separate route from wire data.
Their formats, signatures and identities are unchanged.

The result is a fresh ordinary dictionary with exactly `report.md` and
`continuation.json`, each immutable bytes. It is not a filesystem inventory or a
commitment. No third output is regenerated; the retained canonical source still
participates in complete three-file output accounting. No caller allowances are
serialized. Identical detached content produces identical bytes under any
sufficient allowances, regardless of subsequent store, policy, artifact or clock
changes. Rendering performs no store, artifact, filesystem, environment, clock,
policy, network, model, tool, TeX or inference access. It does not refresh,
authenticate, write or discharge anything.

## Closed continuation and exact facts

The new format is `research_pipeline.lifecycle_report_continuation`, ordinary
integer `version:1`. Its exact top-level fields are `format`, `version`,
`identities`, `saved_work`, `groups`, `continuation`, `ordinary_work_allowed`,
`recheck_required`. The last two are always **false** and **true**. Canonical
serialization is sorted compact ASCII JSON followed by exactly one LF. This is a
generated continuation representation, not a WorkProductManifest, execution
request, committed result or readable-plan descriptor. Historical
`research_pipeline.report_continuation` version 1 is unchanged.

`identities` has exactly:

| Field | Validated source origin |
|---|---|
| `control_operation_id` | Selected original transition request's operation ID |
| `report_operation_id`, `report_revision` | Selected original obligation |
| `run` | Exact selected generic-run reference, distinct from control revisions |
| `source_event` | Obligation's reserved `report_source_id`, revision 1, relationship `lifecycle_report_source`, target kind `event` |
| `snapshot_id`, `scientific_snapshot_id` | Source and scientific snapshot identities |
| `binding_digest` | Original complete binding digest |
| `transitioned_at` | Selected original transition date |
| `observed_at` | Actual first-capture date |
| `scientific_watermark` | Captured scientific audit watermark |
| `resource_sequence` | Captured resource sequence, or null for schema 2 |

The reserved source event is an identity derived from detached data, not proof
that an event exists. No output receipt, committed manifest, plan identity,
filesystem destination or publication date is emitted. `saved_work` and
`continuation` repeat the selected original declarations exactly, including their
saved priority order and unknown estimates, jobs, charges or requirements.

The shared projection supplies these seven groups in this order. All historical
field shapes remain, with these lifecycle extensions:

| Group | Lifecycle facts and extensions |
|---|---|
| `objective_scope_context_outcome` | Original objective/scope/outcome/interpretation/stop reason/context. `lifecycle` has exactly `binding`, `captured_control`, `selection`, `source_qualifications`: complete unchanged original packet, complete captured inspection, original selection, original qualification wording. |
| `results_and_recorded_changes` | Original results and exact arbitrary saved-work baseline. `recorded_changes` is `{"unavailable": {"value": null, "unknown_reason": "Historical report comparison is unavailable for a lifecycle saved-work baseline."}}`. No saved manifest source is read or compared. Empty results retain **No result was established by this report.** |
| `reported_checks_and_unresolved_issues` | Exact Evidence origin/result/uncertainty/failure, conditional/provisional claims, disputed reviews, assumptions and unresolved issues retain their labels. Typed facts keep record ID, revision, kind, operational status, scientific disposition and `saved_typed_fields`; opaque facts explicitly lack typed interpretation. |
| `saved_work_jobs_and_gaps` | Original saved work, incomplete checkpoints, uncertain jobs, gaps and ledger uncertainty. Cancellation is not termination evidence. |
| `dimensioned_resources_and_stopping_decision` | Complete captured resource projections, operation receipts/dates, sequence gaps, unknown usage/liabilities, dimensions and original unavailable declarations. No ancestor/descendant or cache/reasoning double counting. Settlement never rewrites the older transition or establishes science. |
| `saved_prioritized_continuation` | Original plan, authority and notice. `next_action_interpretation` is unavailable with reason `No interpreted next action is established; inspect the saved continuation and checkpoint records.` Saved next-action text in typed checkpoint fields survives unchanged. |
| `inspection_reproduction_and_limitations` | Reproduction, limitations, root categories and every record/artifact route. `source_route` has exactly the original `control_operation_id`, `metadata_method:get_lifecycle_source_operation`, `observation_method:read_lifecycle_source`, `limits_required:true`; `record_methods` is `["get_revision","get_typed_revision"]`, `artifact_method` is `read_artifact`. |

Both admission/authority fields use the existing unavailable grammar and the
reason **Captured authority is historical; current permission and admission are
unavailable.** Operational-stop, job-inventory, reading-does-not-authorize,
accounting and protected-capacity notices retain their historical wording.
Original source qualification wording is attributed retained source content, not
a renderer authentication claim. The lifecycle scope qualifications are exactly:

1. Detached structural consistency only; persisted origin and artifact availability are not authenticated.
2. Generated bytes only; no output commitment, readable plan, publication, or acknowledgment is established.
3. Actual first-capture state, not reconstructed transition-time state; missing facts remain unknown.
4. Reading or rendering grants no readiness, restart, continuation, or worker admission.

Scientific presentation follows `scientific`, then `dossier`, then
`saved_baseline` root occurrences. Intentionally repeated categories preserve
order. Resource evidence and control history are not seeded as scientific results;
all captured records remain in inspection routes. Source validation and presentation
use explicitly bounded closure traversal, preflighting complete inventory and
reference occurrences before traversal allocation, counting every root and edge
before appending, and retaining revision pins, visited handling, missing-record
failures and stops at report-source events/end-of-run manifests. Legacy callers
retain their historical closure behavior.

Caller scientific `max_roots` and original snapshot `max_roots` count distinct
exact `(record_id, revision)` selection pins across all categories, deduplicated
in first-occurrence order. Repeated declaration references do not consume extra
snapshot pins. Source validation bounds its walk by the locally derived
`scientific` occurrence count; presentation uses the ordered
`scientific`+`dossier`+`saved_baseline` occurrence count. Neither is a new public
ceiling. The source reconstruction reservation covers the validation inventory,
and the projection reservation covers the presentation inventory. Repetitions
still consume source bytes/nodes, traversal entries, work and output space.

## Inert Markdown and explicit inspection

The title remains `# Controller-generated state report` with the same seven
headings as the legacy renderer. One shared framing engine puts identities and
each complete group through `view_plan._literal`: four spaces, one canonical
ASCII JSON value, and two LF. All authored Markdown, HTML, URLs, wikilinks, paths,
quotes, backslashes, newlines, NUL, bidi controls and supplementary Unicode stay
escaped literal data. Only fixed generated prose/headings occur outside literals.
No lifecycle links to source.json, README.md, reports/runs paths, manifests or a
presumed sibling continuation file are generated.

The footer describes explicit inspection through a separately opened store with
appropriate limits: the `source_route`, exact
`get_revision/get_typed_revision(record_id, revision)`,
`read_artifact(ArtifactReference(digest,size))`, and existing work-product checkout.
Exact arguments are in the literal record membership/event/ordinal/commit and
artifact digest/size routes. These are inert descriptions, not executed calls or
claims of present availability. Reproduction instructions are never executed.
Legacy v1/v2 navigation, newlines, comparison, resource behavior and output bytes
remain unchanged; report capture and report-view planning still call `render_report`.

## Errors and stage order

`LifecycleRenderArgumentError(ValueError)` identifies invalid arguments/allowances;
`LifecycleRenderValidationError(DomainValidationError)` identifies malformed,
noncanonical or contradictory detached content; `LifecycleRenderLimitError(ValueError)`
identifies an exceeded allowance. There is no offline IntegrityError suggesting
storage authentication. Accepted source errors translate to the corresponding
renderer category with sanitized stage-specific diagnostics. AssertionError,
MemoryError and unexpected implementation exceptions are not logical denials.
Missing or unknown Python arguments remain TypeError.

Precedence after entry is:

1. Validate/detach exact limits and nested source limits.
2. Require exact LifecycleSourceObservation; read retained `_json` directly, requiring exact str.
3. Raw-size/work and lexical node/depth safety gates before strict duplicate-rejecting parsing.
4. Strict parsing and allocation-free canonical occurrence/depth measurement.
5. Source reconstruction reservations, complete accepted semantics and equality to original canonical text.
6. Projection reservation before envelopes, closure, groups, identities or continuation wrappers.
7. Complete output sizing, file/bundle ceilings and final simultaneous work reservation.
8. Escaped output generation, joining, encoding and fresh dictionary return.

Bounded preflight reports the first encountered safety/content failure rather
than continuing unsafe input to choose another error. A forged but fully
consistent detached document can render with the same structural-only
qualification; rehashed semantic contradictions still reject. No public `to_dict`
copy, cached identity or overridden observation method is trusted.

## Exact logical accounting

Charges are deterministic logical representation allowances, not RSS measurements.
They include empty overhead and simultaneous representations even if Python shares
immutable objects. A call has one monotonic reservation counter, no refunds and no
double charge merely because a check is repeated. All comparisons permit equality;
a one-unit deficit rejects. Independent source ceilings and embedded original
restrictions continue to apply. Store-only submission/read allowances are type
validated but do not cause or authorize store access.

Let R be exact retained UTF-8 bytes measured without encoding a copy; P the full
canonical ASCII source bytes; B the canonical size of source resources; O the
number of resource operations; A the number of `create_account`/`allocate`
requests (not supplied account rows). Schema-2 unavailable resources have A=O=0.
Duplicates cannot reduce charges and subsequently fail accepted membership checks.
Let M be the minimum caller scientific `max_metadata_bytes` and selected original
report snapshot `max_metadata_bytes`. Container/scalar types and ranges are checked
before inspecting these arithmetic inputs, without domain reconstruction.

```text
Ws = 64*M + 4096
Wr = 256*(B+1) + 262144*(A+1)*(O+1)
W0 = 4096 + 8*R
W1 = W0 + 64*P + Ws + Wr
W2 = W1 + 256*P + 65536
J  = C + 1
W3 = W2 + 8*(I+G+C) + 4*(H+J) + 2*P + 4096
```

Stage A checks `R <= source.max_input_bytes` and reserves W0 **before scanning or
parsing**. The independent source parser's 8R, node and depth gates also apply.
Stage B measures P before reconstruction; it must fit both source.max_source_bytes
and source.max_result_bytes. It measures B and request-derived counts, then reserves
W1 **before binding/control/snapshot/resource/domain reconstruction, hashing,
canonical serialization or closure**. The source codec separately requires
`8R+64P <= source.max_work_bytes`; scientific Ws and resource Wr must fit their own
work ceilings. Nested/original source restrictions still apply.

Stage C reserves W2 **before projection**. The fixed conservative `256P+65536`
term covers repeated input fragments, complete fixed wrappers, traversal containers
and empty overhead. Projection is linear in retained records/references; there are
no pairwise historical comparisons or artifact expansion. Presentation roots use
the validated occurrence count within this reservation rather than imposing the
deduplicated snapshot-root ceiling on repeated categories. Envelope/reference
ceilings still apply. Derived measurement bounds its traversal by this projection
reservation and at most four fixed wrapper levels beyond the source depth ceiling.

Stage D measures I (identities), G (complete groups) and C (complete continuation,
including all repeated occurrences) with the shared allocation-free canonical
walker. It measures exact H, the UTF-8 Markdown size, including title, opening,
headings, identity/group literals, conditional empty-result sentence and footer.
Each inert literal costs `canonical_size(value)+6`. Fixed non-ASCII prose is
measured in UTF-8 bytes. Sizing never uses dumps, `_json_parts`, `_literal`, or
escaped strings. J includes continuation's single final LF. Require:

```text
max(P,H,J) <= min(render.max_output_file_bytes, original_report.max_output_file_bytes)
P+H+J     <= min(render.max_output_total_bytes, original_report.max_output_total_bytes)
```

Thus source.json is included with no additional LF even though it is neither
returned nor regenerated. Before escaped generation, joining, encoding or returned
output construction, reserve W3. It covers simultaneous projected/repeated source
representations, framing, string/byte assembly and returned copies. **W3 is exactly
the minimum complete render-work allowance** for valid content with otherwise
sufficient source limits. W0/W1/W2 are earlier thresholds only. Accepted retained
content has R=P, but preflight never assumes this before validation. Encoding must
match preflighted H and J; any mismatch is an implementation invariant failure,
never truncation or an enlarged limit.

## Remaining ownership

Rendering advances only the rendering subsets of FOLLOWON-02–04/09/11–13 and the
accepted request/specification obligations. Authentic separate O/X/M output
commitment and immutable complete-history readable plans remain 007-B; automatic
publication/refresh and separately verified acknowledgment remain 008; supplied
current-policy restart/continuation and final FOLLOWON-01–13 audit remain 009.
All 94 requirements, broader D04/M0-E duties and M0-S live/scientific obligations
remain open where previously partial. Source capture itself still produces no
rendered output. No schema, CLI, dependency, runtime provider or admission contract
changes. Controller validation and independent review remain authoritative.
